## Why this matters

`pnpm audit --prod` reports **7 vulnerabilities (5 high, 2 moderate)**, all in
transitive dependencies of build/dev tooling — none ship in the app bundle:

- `@xmldom/xmldom` <0.8.13 (the 5 high — XML injection / uncontrolled
  recursion) via `@bacons/apple-targets > @bacons/xcode > @expo/config-plugins`
  — runs during `expo prebuild` (iOS project generation).
- `uuid` <11.1.1 (moderate) via the same chain / `@expo/cli`.
- `tar` <=7.5.15 (moderate, GHSA-vmf3-w455-68vh) via
  `heroui-native-pro > heroui-pro`.

Runtime user risk is low, but these run on developer machines against
repo-controlled inputs and keep the audit signal noisy — a clean audit makes
FUTURE real advisories visible.

## Steps

### Step 1: Add the overrides

In `package.json`, inside the existing `"pnpm"` block:

```json
  "pnpm": {
    "onlyBuiltDependencies": [ ...keep as is... ],
    "overrides": {
      "@xmldom/xmldom@<0.8.13": ">=0.8.13",
      "uuid@<11.1.1": ">=11.1.1",
      "tar@<7.5.16": ">=7.5.16"
    }
  }
```

Scoped-range override syntax keeps unrelated major versions untouched (e.g. a
package legitimately pinning uuid v9 for API reasons would break on a blanket
override — the range form only rewrites vulnerable ranges).

Run `pnpm install`.

**Verify**: `pnpm audit --prod 2>&1 | tail -3` → `0 vulnerabilities` (if some
remain, list them — they are NEW findings, not these three).

### Step 2: Prove the toolchain still works

- `npx tsc --noEmit 2>&1 | grep -c "error TS"` → `5`.
- `npx vitest run` → no new failures.
- `npm run prebuild:dev` → exit 0 (this is what exercises
  `@bacons/xcode`/xmldom). If prebuild cannot run in your environment (no
  macOS/CocoaPods), STOP after the first two checks and report that prebuild
  verification is pending on the operator's machine.
